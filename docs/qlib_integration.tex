\section{What the integration delivers}

The quantitative desk adds a machine-learned layer on top of the deterministic
valuation engine and the fundamentals warehouse:

\begin{itemize}
  \item \textbf{Return prediction} --- a cross-sectional LightGBM alpha model over
        the monthly fundamentals panel, producing a per-name expected forward
        return (the \code{mu} consumed by the optimizer and the scanner).
  \item \textbf{Risk prediction} --- a factor-structured forward covariance
        (\code{StructuredCovEstimator}), $\Sigma=F\,\Sigma_B\,F\tr+\diag(\mathbf d)$,
        with its decomposition exposed to the enhanced-indexing optimizer.
  \item \textbf{Portfolio optimization} --- both a native optimizer \emph{and}
        qlib's optimizers, selectable at runtime.
  \item \textbf{Score enhancement} --- the learned alpha plus regime-conditioned
        factor-IC weights blended into the value $+$ sentiment interest score.
  \item \textbf{Committee integration} --- a \code{quant\_signals} evidence node and
        a Quantitative Factor Analyst specialist.
  \item \textbf{Agentic model research} --- a LangGraph loop in which a quantitative
        researcher, a model validation unit, a portfolio manager and an external
        advisor iterate over the training specification, producing a validation
        report per round and gating promotion on out-of-sample improvement
        (\S\ref{sec:research}).
  \item \textbf{REST $+$ UI} --- a \code{/api/quant/*} router and a \emph{Quant} tab.
\end{itemize}

Everything degrades gracefully: with no trained model, or with qlib or an optional
dependency absent, each surface returns a defined fallback and the application runs
unchanged.

\begin{keybox}[The lean-embed principle]
qlib's model, risk estimator, optimizers, and evaluation run as \emph{plain
libraries} on a MultiIndex DataFrame the app builds from Postgres. The integration
never uses qlib's expression engine, its \code{.bin} data provider, the Alpha158/360
handlers, or the recorder/\code{qrun} workflow --- so there is no \code{qlib.init},
no data-provider bootstrap, and no mlflow tracking backend. Only \code{lightgbm},
\code{scikit-learn}, and \code{cvxpy} become hard new runtime dependencies.
\end{keybox}

\section{The panel adapter}
\code{qlib\_data.build\_panel} produces a qlib-style MultiIndex frame --- rows
$(\text{datetime},\text{instrument})$, columns
$(\text{feature}\,|\,\text{label})$ --- consumed directly by
\code{DataHandlerLP.from\_df}. Features are importance-ranked fundamentals from four
families, cross-sectionally $z$-scored per month; the label is the forward 1m/3m
return; fundamentals are aligned point-in-time ($\text{period\_end}+90\text{d}\to$
month-end). This is the \emph{same} loader and alignment the regime-IC research
uses, so the production forecast and the research signal share one lookahead-safe
data path. The alpha model trains through the real qlib \code{DatasetH} pipeline;
the \code{AlphaLGB} subclass attaches LightGBM's callbacks directly in \code{fit},
so training runs with plain LightGBM and needs no \code{qlib.init} or tracking
backend. Prediction runs the stored booster on any reindexed feature matrix.

\section{Dual optimizer dispatch}
\code{qlib\_optimize.solve(optimizer, tickers, mu, sigma, \dots)} dispatches to
either backend family and returns a uniform \code{PortfolioSolution} (weights,
annualized expected return / vol / Sharpe, factor exposures, diagnostics):

\begin{center}\small
\begin{tabular}{@{}>{\ttfamily\footnotesize\color{navy}}l p{5.0cm} p{5.0cm}@{}}
\toprule
\normalfont\tabhead{\ttfamily optimizer} & \normalfont\tabhead{Engine} & \normalfont\tabhead{Notes} \\
\midrule
native & \code{optimize.py} (SLSQP / cvxpy-MIP) & Full constraints: sector caps, vol cap, cardinality, turnover. \\
qlib\_mvo / \_gmv / \_rp / \_inv & qlib \code{PortfolioOptimizer} & Mean-variance / min-variance / risk-parity / inverse-vol; long-only, fully invested. \\

\bottomrule
\end{tabular}
\end{center}

Both families are fed the same annualized $\muv$ (alpha or historical mean) and
$\Sigma$ (qlib-structured, Ledoit--Wolf, or sample). Neither is a default-only path
--- both ship enabled and are chosen per request or from the UI selector.

\section{Score enhancement: alpha $+$ regime-IC weights}
The value $+$ sentiment interest score (\code{screener\_agent}) blends two learned
inputs on top of the fundamental composite:

\begin{enumerate}
  \item \textbf{Normalized alpha} $v_\alpha$ --- the qlib model's expected return,
        cross-sectionally normalized, as the dominant term (default weight $0.40$)
        when the model covers the shortlist.
  \item \textbf{Regime-IC family weights} --- the fundamental score budget
        (value / growth) is re-split by how predictive each family has been
        \emph{in the current macro regime} (\S\ref{sec:regime}), rather than by
        fixed constants.
\end{enumerate}

When no trained model or IC data is available the score reduces exactly to the
fixed-weight composite (guaranteed by test). Each row reports \code{alpha},
\code{alpha\_percentile}, and a \code{score\_components} breakdown; the response
carries a \code{scoring} block naming the weights and model actually used.

\section{Where the macro-regime IC feeds forecasting}
\label{sec:regime}
The macro-cycle model (HMM / VAE) labels each month with a regime; the regime-IC
engine then computes, \emph{conditioned on that regime}, the Spearman rank IC of
every fundamental metric against forward returns, into
\code{fact\_equity\_factor\_ic\_regime}. The one live consumption path in the desk
is scoring: \code{ic\_weights.family\_weights} reads the latest regime's rows,
aggregates per-metric $|\text{IC}|$ to family-level emphasis, and the scanner
re-splits its fundamental budget accordingly --- so the interest score leans harder
on whichever factor family the current regime says is most predictive.

\begin{notebox}[Scope]
The LightGBM alpha model itself is regime-\emph{agnostic}: it learns from factor
\emph{values} (including momentum/volatility from the market-factor family), and
the regime enters forecasting through the score weights, not as a model feature.
The committee receives macro regime context from the macro node and the
\code{quant\_signals} block, but not the factor-IC table directly.
\end{notebox}

\section{Committee integration}
\begin{itemize}
  \item \textbf{State} --- \code{InvestmentCommitteeState.quant\_signals} plus a
        config toggle \code{enable\_quant\_signals}.
  \item \textbf{Evidence node} --- \code{qlib\_signals\_node} runs in the
        \emph{prepare} phase (once, shared across providers): the ticker's alpha
        expected return, universe percentile, and model rank-IC, plus a peer-group
        factor-risk read (forward vol, factor exposures, minimum-variance weight).
        It auto-fans-out from the engine and auto-fans-in to every analyst, and
        degrades to \code{available: false} on any error, so it never fails a run.
  \item \textbf{Specialist} --- the Quantitative Factor Analyst reconciles the
        statistical alpha/risk signals with the fundamental/DCF thesis and flags
        alpha-vs-valuation disagreements.
\end{itemize}

\section{Agentic alpha research (LangGraph)}
\label{sec:research}

\emph{Code:} \code{api/quant/research/}. The one-shot trainer fits one model on one
fixed parametrization and promotes whatever comes out. This package replaces that
with a critiqued search: four agents iterate over the training specification, each
round emits a full model validation report, and promotion is gated on beating the
incumbent out-of-sample.

\begin{keybox}[Why a loop, and why critics]
A single fit has no mechanism for noticing that its own number is untrustworthy. On
the shipped US \code{forward\_12m} model the purged walk-forward rank-IC of the
baseline specification is \emph{negative} ($-0.013$); two preprocessing changes ---
median imputation and label winsorization --- move it to $+0.017$. Neither change is
exotic, and neither would be tried by a pipeline with no critique step. The critics
exist because a search will otherwise optimize the headline: a model can improve its
rank-IC purely by discarding a third of the universe.
\end{keybox}

\subsection{State and reducers}

\code{AlphaResearchState} is a \code{TypedDict(total=False)} following the
committee's convention. Exactly three channels accumulate, and they are exactly the
channels written concurrently by the fan-out:

\begin{center}\small
\begin{tabular}{@{}>{\ttfamily\footnotesize\color{navy}}l >{\ttfamily\footnotesize}l p{6.2cm}@{}}
\toprule
\normalfont\tabhead{Channel} & \normalfont\tabhead{Reducer} & \normalfont\tabhead{Contents} \\
\midrule
iterations   & operator.add & One validation report per completed round. \\
agent\_notes & operator.add & The four personas' output; written by three parallel nodes. \\
candidates   & operator.add & Fitted models kept for champion selection and ensembling. \\
\bottomrule
\end{tabular}
\end{center}

Everything else is last-write-wins, which is what a loop that overwrites its working
specification each round requires. Heavyweight objects --- the raw panel, the fitted
candidates --- live on the state as ordinary Python references: the graph runs in one
process on one thread, so there is no serialization boundary, and re-deriving a
multi-minute warehouse pull each round to satisfy a purity principle would be the
wrong trade.

\begin{notebox}[Node names may not collide with state keys]
LangGraph rejects a graph whose node name matches a state key. The obvious names
\code{report}, \code{validation} and \code{researcher} are all taken by channels, so
the nodes are \code{build\_report}, \code{model\_validation} and
\code{quant\_researcher}. The failure is a hard \code{ValueError} at
\code{add\_node}, not a subtle one.
\end{notebox}

\subsection{Routing and termination}

\code{route\_after\_prepare} ends the run immediately when the warehouse yields no
usable panel, rather than looping over emptiness. \code{route\_iteration} has five
independent stopping conditions, evaluated in priority order --- cancellation; the
iteration budget; a portfolio-manager \code{accept}/\code{reject}; the researcher
declaring convergence or proposing nothing the validator accepted; and the guarded
metric failing to improve for \code{patience} rounds. Each is recorded in
\code{stop\_reason}, so the report states why the run ended instead of leaving the
reader to infer it from the round count. The recursion budget is
$12\times\text{\code{max\_iterations}}+20$, giving the eight-node body headroom.

\subsection{The agents}

Three of the four run on the desk provider (DeepSeek by default, any registry
provider by request). The External Advisor runs on a \emph{different} provider when
the caller supplies a second key, so the outside view carries genuinely different
priors; it falls back to the desk provider otherwise.

Structured output uses the committee's plumbing (\code{make\_chat\_model(\dots)}
\code{.with\_structured\_output}) with retry-on-malformed. Enum-like fields are typed
\code{str}, not \code{Literal}, and normalized in code --- the committee's convention,
adopted for the same reason: a model answering ``PASS'' should not lose an entire
analysis to whole-response validation.

\begin{notebox}[The deterministic path is not a stub]
\code{MZQA\_COMMITTEE\_DISABLE\_LLM=1}, \code{config["offline"]}, or simply no key
puts the loop on a fully deterministic path: the researcher walks a pre-registered
ladder of changes motivated by the incumbent pipeline's known defects, and the three
critics apply rule-based versions of their checklists. It is a usable no-token grid
search, and it is what the test suite exercises.
\end{notebox}

\subsection{Two hard boundaries}

\textbf{The LLM never runs code.} Following FlowMind, each agent's system prompt is a
\emph{lecture} over the \code{TrainingSpec} schema, generated from
\code{describe\_search\_space()} so it cannot drift from the validator. The
researcher returns a patch; \code{apply\_patch} whitelists every key, range-clamps
every value, drops hyperparameters foreign to the selected model family, and reports
what it rejected back into the next round's packet. A hallucinated field, or a
\code{learning\_rate} of $500$, cannot reach a fit.

\textbf{The LLM never sees instrument identity.} Agent packets are built by an
explicit allowlist and then swept: aggregate metrics and bucket statistics only, no
per-name returns, no ranked name lists. The guard matches against the run's
\emph{actual} universe rather than against anything ticker-shaped, and inspects
identifier positions rather than prose --- US symbols include \code{ALL}, \code{ON},
\code{MAX}, \code{GAP} and \code{REAL}, so a text scan fires on almost every sentence
an agent writes. The motivation is concrete: every current model's training data
covers the evaluation window, so a packet naming the winners of 2023 would let an
agent steer the specification toward them for reasons unrelated to the diagnostics.

\subsection{Background job and ledger}

A run is several fits plus a dozen LLM calls --- past any request timeout --- so it
cannot use the blocking shape \code{/retrain} uses. \code{runner.start\_run} registers
the run, spawns a daemon thread, and returns a \code{run\_id} immediately; the client
polls. Rounds are persisted by an \code{on\_iteration} hook as they complete, then
re-persisted at the end once the critics' verdicts for each round exist. One active
run per \code{(model\_key, label)} is enforced both in-process and in the ledger,
because two runs training the same model would race on the artifact path at
promotion.

Tables (migration \code{136\_quant\_alpha\_research.sql}, also created idempotently by
\code{runner.\_ensure\_tables}): \code{quant\_alpha\_research\_run} --- the header the
UI polls, carrying status, live stage, champion, and the promotion decision --- and
\code{quant\_alpha\_research\_iteration} --- one row per round with the specification,
the battery, the rating, both breakdowns, and all four verdicts.

\subsection{Promotion}

\code{select\_champion} considers every round the Model Validation unit did not veto,
\emph{plus} an ensemble of them, and promotes only when the champion beats the
incumbent on the guarded metric by a margin, the Portfolio Manager accepted, and the
robustness rating is not \emph{fragile}. Otherwise the artifact is written to a
candidate path, the live model is untouched, and \code{promotion\_reason} records
why. When every round is vetoed the run still names its best attempt, explicitly
flagged as not promotable --- more useful than reporting no champion at all.

\begin{notebox}[The incumbent comparison flatters the incumbent]
The production model's recorded rank-IC comes from a single held-out block with no
embargo; the champion's comes from a purged walk-forward. The two are not
commensurable, and the promotion reason says so on every run.
\end{notebox}

\section{Operations}

\begin{itemize}
  \item \textbf{qlib on Python 3.13.} No PyPI wheel exists for 3.13, so qlib is
        built from a bundled clone and installed non-editable, so \code{import qlib}
        resolves from any working directory (the C++ toolchain is required for the
        build). Lean runtime deps are pinned in \code{backend/requirements.txt}
        (\code{lightgbm}, \code{scikit-learn}, \code{cvxpy}, \code{ecos},
        \code{dill}, \code{pyarrow}, \dots).
  \item \textbf{Cold start / pre-warm.} The first alpha call for a jurisdiction
        builds the cross-section panel from the warehouse and then caches it (TTL
        via \code{QLIB\_ALPHA\_CACHE\_TTL}); the walk-forward backtest is cached
        separately. Both are pre-warmed on startup so the first user request is
        served from cache.
  \item \textbf{Retraining.} The alpha model is (re)trained via the CLI:
        \code{python -m api.quant.qlib\_alpha train -{}-jurisdiction US}; artifacts
        are persisted per jurisdiction and hot-reloaded on file mtime.
  \item \textbf{Agentic research runs.} A run is a background job, not a request:
        \code{POST /api/quant/research/start} returns a \code{run\_id} and the work
        continues on a daemon thread, with rounds persisted to
        \code{quant\_alpha\_research\_\{run,iteration\}} as they complete. Apply
        migration \code{136\_quant\_alpha\_research.sql} (or let
        \code{runner.\_ensure\_tables} create the tables on first use). Run it
        headless with
        \code{python -m api.quant.research.graph -{}-jurisdiction US -{}-label forward\_12m},
        adding \code{-{}-offline} to walk the deterministic ladder without spending
        tokens. Expect the warehouse pull to dominate the first minutes: the full US
        panel is the expensive step, and it is loaded once per run and reused by
        every round.
  \item \textbf{Tests.} \code{backend/api/quant/tests/test\_quant.py} covers the
        optimizer backends, the structured covariance, the exact scoring fallback,
        the alpha blend, the IC re-split, and a DB-gated panel/train smoke test.
\end{itemize}
